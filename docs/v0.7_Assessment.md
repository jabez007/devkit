# v0.7 assessment: shell workflows and worktree compatibility

Assessed October 31, 2026, starting from `6eb43fd` (writable Beads 0.2.0).
This dated assessment describes the baseline before implementation.
[The November 1 update](#implementation-update-november-1-2026) records delivered
reference discovery and sequential linked-worktree support.

The next milestone should improve everyday verification and evidence retrieval,
then qualify linked Git worktrees. No new Odoo capability or orchestration layer
is needed.

## Baseline and design note

[Hosted checks](https://github.com/jabez007/devkit/actions/runs/41238716058) and
[the CI pilot](https://github.com/jabez007/devkit/actions/runs/41238716067) both
succeeded on the starting revision. The [workflow](../.github/workflows/checks.yml)
pins Linux/Python/Go tooling and verifies the Beads 1.3.2 archive checksum.
[Import boundaries](../pyproject.toml) prohibit optional integrations in the core;
[wheel acceptance](../scripts/check_wheels.py) tests foundation-only, Go-only and
Odoo-only installations without Beads. The existing association and lifecycle
suites cover authorization, transport parity, uncertain writes, cancellation,
conflicts, retention and retries; see [Beads integration](Beads_Integration.md).

Reuse `CommandService`, `CommandSpec`, `Beads.workspace`, `run_process`, exact
project policy grants and `RunStore.reference`. The adapter remains the deep
module that hides native Beads response details. Core owns invocation and evidence,
not task transitions. No new dependency or contract is necessary for this assessment.

The small implementation change is at the CLI presentation seam: `doctor` and
`check` text output now expose the child check's status, summary, reason and a
project-qualified evidence retrieval command. Previously they hid those details
behind “Prerequisite checks did not succeed” or “Required check results”. JSON,
Python, MCP, exit codes, grants and persisted results remain unchanged. Regression
coverage invokes the actual CLI and compares stored child results. The diagnostic
test failed against the original renderer. Ruff's complexity gate passed before
changes; `render` remains 6 and the new `render_checks` is 4, below the limit of 10.

No unrelated cleanup is required. Repeated native workspace checks add process
startup cost, but protect identity across prerequisites and invocation. Caching
would need an invalidation design; do not remove these checks to save subprocesses.

## Workspace compatibility at the assessment baseline

Reviewed the pinned upstream [worktree guide](https://github.com/gastownhall/beads/blob/v1.3.2/docs/reference/worktrees.md),
[storage guide](https://github.com/gastownhall/beads/blob/v1.3.2/docs/architecture/dolt.md),
[context implementation](https://github.com/gastownhall/beads/blob/v1.3.2/cmd/bd/context_cmd.go)
and [embedded store](https://github.com/gastownhall/beads/blob/v1.3.2/internal/storage/embeddeddolt/store.go).
These are Beads capabilities, not a claim of Devkit support.

| Configuration | Evidence | Devkit support |
| --- | --- | --- |
| Main Git checkout, embedded Dolt | Full lifecycle and verification exercised | Supported on the pinned Linux baseline |
| `git worktree add`, shared embedded ledger | Native context, reads and sequential creates exercised | Blocked by current adapter |
| `bd worktree create`, shared embedded ledger | Same native probes exercised | Blocked by current adapter |
| Concurrent embedded writers | Not exercised; engine owns locking | Not certified; no guard removed |
| External `BEADS_DIR` / redirects | Documented upstream; not exercised here | Blocked / ambient override filtered |
| Direct or shared Dolt server | Reviewed supported native configuration; no `dolt` executable available locally | Blocked; no server acceptance claim |
| Proxied server | Upstream `init --help` labels it experimental | Unsupported and untested |

Both worktree creation methods resolved `beads_dir` and `repo_root` to the main
checkout, `cwd_repo_root` to the linked checkout, `is_worktree=true`, and the same
project UUID. Native writes were visible from the main checkout. The fixture's
tracked `.beads` metadata did not create another ledger. Devkit returned
`UNSUPPORTED_BEADS_WORKSPACE`. With no checkout-local `.beads` directory, the
current earlier guard instead returns `BEADS_NOT_INITIALIZED`.

The blockers are concrete: [the adapter](../packages/devkit_beads/src/mccann_hub/devkit_beads/client.py)
sets `BEADS_DIR` to the selected checkout, requires a real local directory, rejects
worktree/redirect flags, and equates the native repository root with the invocation
root. Removing just one check would neither establish workspace identity nor
preserve authorization of the shared location. Do not recommend initializing a
second ledger in each worktree as a workaround.

Native embedded discovery does not establish concurrency safety. The upstream
store delegates concurrency to its embedded driver; its explicit file lock is
for initialization. Test contention rather than infer guarantees from the guide's
single-writer description. Server setup, credentials, recovery and synchronization
remain operator/Beads responsibilities; Devkit must not start a server or invent
a parallel lock service. No server or cross-machine compatibility was exercised.

## Gaps and independently testable v0.7 slices

1. **Shell diagnostics — implemented in this assessment.** Show existing child
   diagnostics and retrieval commands. Accept with CLI regressions, unchanged
   envelopes and the full existing gates. No Beads-specific rendering in core.
2. **Evidence discovery — next small foundation slice.** Add an exact reference
   filter to `runs list` using existing reference files and pagination, without an
   index database. Test project isolation, no matches, repeated associations,
   corrupt metadata, retained families and foundation-only retrieval. Expose a
   shell example for “find verification for this work item”. Keep current schemas
   and operator-only maintenance semantics; do not add task lookup logic to core.
3. **Linked worktrees — adapter slice after the acceptance design below.** Use
   native discovery, validate the resolved shared workspace, retain explicit
   checkout authorization and native issue identity. No extra task store or
   Devkit synchronization. Begin with local, sequential embedded operation;
   concurrent writes and servers are separate qualification work.
4. **Independent plugin publication readiness.** The renamed README-check plugin
   already builds outside the workspace, installs, discovers, activates, runs via
   CLI/Python/MCP, persists evidence and uninstalls independently
   ([acceptance](../scripts/check_third_party.py)). Before public publication,
   decide owned distribution names and licensing, complete package README/license
   metadata, and define supported Python/dependency/API compatibility ranges.
   There is currently no repository license. This assessment also reproduced an
   installed typing failure (`import-untyped`) and adds the missing foundation
   `py.typed` marker. The independent consumer test accepts a valid result and
   rejects an invalid status; no runtime API changes or new dependencies are needed. Keep test helpers local
   until copying them demonstrably causes maintenance problems; no SDK needed now.
5. **Server/concurrency qualification — later, conditional.** Pin the native
   server tooling, use isolated loopback configuration, then prove competing
   claims, guarded updates, lock waits, cancellation and restart/retry behavior.
   No new runtime guarantee until these tests pass. Shared/proxied/remote modes
   should not be enabled as a side effect of accepting one direct server mode.

## Worktree design and acceptance gate proposed October 31

Keep `Context.project_root` as the actual checkout used for configuration, policy,
process execution and evidence. Keep Beads UUID as the task identity. Two checkouts
can refer to one issue while producing distinct project-scoped verification runs.
Association should initially accept only runs from the invoking checkout; an
operator can retrieve other checkout evidence with existing explicit scope tools.
Do not silently broaden run access because two checkouts share a ledger.

First attempt this entirely inside the adapter: use native context discovery with
ambient `BEADS_DIR` removed, validate the Git common directory and registered
worktree relationship through supervised Git plumbing, and require the native
main root and shared `.beads` location to match that relationship. Bind subsequent
calls to that validated workspace and recheck identity before writes. Reject
external redirects, mismatched UUIDs, unregistered checkout paths and symlink
escapes. The initial topology is a normal main checkout plus its linked worktrees;
bare repositories and externally stored ledgers are excluded.

Retain exact operator command grants on each invoking checkout. A grant to the
main checkout must not authorize siblings. Document that an authorized Beads
operation uses that checkout's native shared ledger, and version the adapter so
operators must renew exact-version trust for the broadened topology. Repository
options must not select arbitrary external workspaces. No new configuration is
proposed unless these native checks prove insufficient; in that case stop and
revise this design before enabling support. Devkit policy is a capability grant,
not filesystem sandboxing, and these checks do not isolate a hostile Git/Beads
installation or eliminate all filesystem races.

Before changing the current rejection, automate: main + two linked checkouts;
Git-created and Beads-created worktrees; with and without local metadata;
unrelated repositories and forged/moved Git metadata; symlink/redirect escape;
denied checkout with zero mutation; read-only grants; explicit claim/update/close;
correct checkout revision in evidence; idempotent associations and pruning;
CLI/Python/MCP parity; cancellation during native lock waits; and native concurrent
contention without lost updates. Report contention failures conservatively and do
not replay uncertain writes. Keep concurrency claims narrower than topology support.

## Developer ergonomics

Setup currently needs tool installation, plugin selection, a check profile,
external exact-version trust and scoped command grants. These serve distinct
purposes. Reuse the single [Beads policy example](../examples/beads/policy.toml)
and existing reusable policy profiles; avoid another profile family or wizard.
Explicit `--project` is needed when invoked from an editor/subdirectory because
[configuration](../packages/devkit/src/mccann_hub/devkit/config.py) selects that exact root.
Do not make it an automatic worktree-to-main-checkout redirect.

Use native `bd` for rich task browsing, dependency editing, synchronization and
administration. Devkit's lifecycle subset is justified by shared authorization and
evidence; expanding it to mirror every native flag would add little value.
`runs show` and copied evidence work without Beads, but retrieving evidence starting
from a task reference currently requires inspecting run listings. That is the most
useful next foundation improvement. No editor plugin or agent harness is needed.

## Implementation update: November 1, 2026

The first two requested implementation slices are delivered. Reference discovery
uses the existing operator interface: `runs list --reference STRING` matches
arbitrary exact strings before pagination, within the selected project unless
`--all-projects` is explicit. It reads the existing reference metadata and reserved
`work_item_ref`. It does not load plugins, mutate evidence or change retention.
Corrupt metadata still fails the entire scan, including nonmatching records.
Installed acceptance removes Beads before retrieving its references.

`devkit-beads` 0.3.0 supports a main checkout and registered linked worktrees on
one Beads 1.3.2 embedded ledger, operated sequentially. Renew exact-version trust
and explicitly list each checkout in the operator policy. Native discovery runs
with ambient workspace overrides removed. The adapter verifies the Git common
directory, registration and backlink, compares native Beads paths, and binds
subsequent calls to the shared directory. It rechecks identity before writes.
Server modes, external redirects, bare repositories, separate Git directories,
symlink escapes and unregistered paths remain rejected.

Workspace data adds the invoking checkout, main workspace root, worktree flag
and `concurrency="sequential-only"`. The command registry, effects, invocation
surfaces, plugin API and evidence envelope remain unchanged. Configuration,
authorization, verification revision and evidence scope remain per checkout.
A shared task UUID does not authorize associating another checkout's run.

The [installed workflow](../scripts/check_beads_workflow.py) creates a Git worktree
without local `.beads` metadata and a Beads-created worktree with metadata.
It verifies three distinct revisions, main-only grant denials, explicit checkout
grants, shared create/claim/update/close, association parity on CLI/Python/MCP,
cross-checkout association rejection, filtered retrieval and protected retention.
[Topology tests](../tests/test_beads_worktrees.py) cover forged/copied Git files,
invalid backlinks, native moves requiring new grants, missing shared ledgers,
symlinks, redirects, native path/UUID mismatches, renewed version trust and
cancellation. The initial happy-path, redirect and UUID-recheck regressions failed
before implementation.

The requested scope qualifies sequential operation only. The earlier proposal's
contention gate is deferred rather than claimed complete. Simultaneous writers
are not detected or serialized by Devkit and remain unqualified until native
concurrency testing establishes safety. No task database, process scheduler or
lock service was added. Trusted executables and non-hostile filesystem state
remain assumptions; identity rechecks do not eliminate all filesystem races.

The remaining roadmap priorities are publication and compatibility decisions,
then separately scoped server/concurrency qualification. No additional Odoo
validators or orchestration work was introduced.
